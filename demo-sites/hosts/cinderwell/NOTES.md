# Cinderwell Community Pantry (host site, charity id demo-pantry-a)
- Structure: index.html (header, quote hero, tile row, who we serve, history/what we do, feature, news x5, slot, newsletter + donate band, footer), donate.html, about.html, get-food.html. Static, no build. `styles.css` has class selectors only, so injected slot content is never restyled; no rules on `.ct-*`.
- Contract: three empty `data-impact-slot` sections on every page, each inside `.wrap` (1180px column); `[data-impact-slot]:empty{display:none}`; every Donate link is `a[data-impact-donate][href="donate.html"]`; layer script tag with `data-charity="demo-pantry-a"`; `--ct-*` vars on :root.
- Palette: deep teal #0f5b57 / #0a3533, marigold #f2b632, cream #fbf6ea, ink #1c2b2a, muted #4a5a58. Type: Besley (display) + Atkinson Hyperlegible (text), self-hosted in `fonts/` (OFL files included).
- Art: all SVG in `img/` (hero, tile, poster, five news thumbs, map, favicon) generated procedurally; wordmark logo is inline SVG in each header/footer. Nothing is a photo or a real logo.
- Preview: `?preview=1` (filled) or `?preview=empty` runs `preview.js` with `donor-view.*.json`; `site.js` also loads `preview-slots.css` (copy of `docs/design/ct-slots.css`) in preview mode only, because the real layer bundles those styles. Copy is refreshed by hand if the CSS changes.
- Verified in browser (tab closed after): 1280/768/390 on all four pages, no horizontal overflow (scrollWidth equals viewport); index and donate in plain and ?preview=1 states at desktop and 390; hamburger toggles aria-expanded and opens a full-width list; internal links and #anchors checked by script; header Donate, nav, buttons are at least 44px tall.
- Layer button note: `.ct-next-link` renders about 42px tall from the layer's own padding (host does not override it). White text on #0f5b57 passes AA.
- Honest figures: every stat names its year and basis (2025, weighed counts, sign-in sheets). Names, address, phone (555 range) and `.example` email are fictional. Footer social links point at example.com.

## Contract v2 usage (index.html only)
- Regions (default markup stays for strangers; `<template data-impact-for="NAME">` at the end of `<main>` is cloned for a recognized donor): `greeting` (empty strip above the header, requires firstName, `:empty{display:none}`), `hero` (wraps the founder-quote hero, id `impact`), `stat` (the middle stat tile itself, requires since), `next` (empty callout above the volunteer section, requires next), `band` (the `.band-donate` half, requires next). The three v1 slot sections are gone from index.html; about/donate/get-food keep their v1 slots.
- One empty `<div hidden data-impact-slot="regions">` stays on index.html on purpose: the layer returns early when the page has no `[data-impact-slot]` at all, so without it regions never paint. The slot name is unused, so it is never filled.
- Every number or sentence about the donor is a `data-ct-*` field. Estimates render only through `data-ct-text="estimate"` and sit in dashed, italic, un-filled boxes labelled "Your share, an estimate"; records use the site's own `.tile.tile-stat` component (limit 3 in hero, 1 in the stat tile).
- Re-composition: CSS under `html[data-impact-active]` turns `<main>` into a flex column and sets `order`: hero, tiles, next, volunteer (id `volunteer`), band, news, who we serve, our story. Strangers keep DOM order. Swapped regions fade in over .5s (opacity only, off under prefers-reduced-motion); `.hero-region` keeps the default hero's min-height so the swap does not collapse.
- `site.js` copies the layer-rewritten donate href (header button is the reference) onto `a[data-impact-donate]` links that appear after the rewrite, because the layer rewrites those links once, before templates are cloned.
- Contract gaps hit: (1) layer.ts `fillFact` leaves `data-ct-text` on cloned repeater nodes, then `fillNode`'s scalar pass removes them (count, unit, date, note, estimate all vanish); fix is `removeAttribute("data-ct-text")` after `textContent`. Verified with a patched bundle served from the scratchpad; the site itself was not changed to work around it. (2) The layer start gate needs a `[data-impact-slot]` (see above). (3) `nextStep.href` is only set for give kinds, so the next-step link often disappears and the secondary CTAs vanish with it. (4) No scalar for a short next-step label, and no OR/age logic (cannot say "show hero only if story or records"). (5) Region dates: no `data-ct-if` for sinceDate. (6) `data-impact-active` is set inside requestAnimationFrame, so in a hidden tab it never lands; there is a one-frame gap between swap and re-order.
