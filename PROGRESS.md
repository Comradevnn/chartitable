## Integration contract (demo sites ↔ layer) — **v1 LOCKED**
```html
<!-- in <head> or end of <body> -->
<script src="https://<layer-host>/layer.js" data-charity="<charity-id>" defer></script>

<!-- anywhere in the page; leave them EMPTY -->
<section data-impact-slot="hero"></section>              <!-- big personalized impact block -->
<section data-impact-slot="since-last-visit"></section>  <!-- what changed since last visit -->
<section data-impact-slot="next-step"></section>         <!-- one tailored suggestion -->

<!-- the site's donate button -->
<a data-impact-donate href="#donate">Donate</a>
```
- **Charity IDs:** `demo-pantry-a` (site one), `demo-pantry-b` (site two). Display names are Teammate 1's choice — must be fictional (D5).
- **Empty by default:** slots render nothing for unrecognized visitors; the site must look complete without them. Recommended CSS: `[data-impact-slot]:empty { display: none; }`
- **State hooks:** when a donor is recognized, the layer sets `data-impact-active` on `<html>` and `data-impact-state="ready"` on each filled slot. Sites can style around these (e.g. shrink the generic hero).
- **Donate button:** the layer rewrites the `href` of `[data-impact-donate]` to the hosted donate page for this charity. Without JS the site's own href stays.
- **Token:** arrives as `?ct=<token>` (from email link or donate redirect). The layer stores it in `localStorage` under `chartitable:<charity-id>` (try/catch) and removes it from the address bar with `history.replaceState`.
- **Markup the layer injects:** classes prefixed `ct-`. Logged facts use `.ct-record`; computed numbers use `.ct-estimate` and always carry the visible word "estimate"/"about". Photos use `.ct-photo`.
- **Theming:** set CSS variables on `:root` or on a slot: `--ct-accent`, `--ct-fg`, `--ct-bg`, `--ct-muted`, `--ct-font`, `--ct-radius`. Layer default styles use `:where()` (zero specificity) so site CSS always wins.
- **Local dev:** until Vercel is up, use `<script src="http://localhost:5174/layer.js" ...>`.

## Integration contract — **v2** (Sat 8:35 AM; additive, v1 pages keep working unchanged)
Full spec with rationale: `docs/PLAN_DYNAMIC_SITE.md` §2. Layer support lands in T25 (regions, conditions, fields) and T28 (live, motion); until then only the prototype subset in `layer/src/layer.ts` works.
```html
<div data-impact-region="hero" data-impact-requires="story|records"> …default markup for strangers… </div>
<template data-impact-for="hero" data-impact-when="state:just_gave" data-impact-variant="just-gave"> … </template>
<template data-impact-for="hero" data-impact-variant="thanks"> … </template>  <!-- no `when` = default donor template -->
```
- **Regions** keep their default markup for strangers. For a recognized donor the layer clones the first `<template data-impact-for>` whose `data-impact-when` matches (a template without `when` is the default) and fills it. No match or an empty fill → default markup stays. No `data-impact-slot` is needed on a v2 page.
- **Conditions** (`data-impact-requires`, `data-impact-when`, `data-ct-if`): `|` = OR, `+` = AND, `!` = NOT. Keys: `firstName story body headline records estimates since sinceRecords sinceEstimates sinceDate photos next nextHref gifts thin repeat`, `state:<just_gave|news|first_impact|repeat|lapsed|returning>`, `trait:<named|has_photos|regular>`. Unknown key = false.
- **Fields, textContent only:** `data-ct-text` = `firstName headline story body nextText nextLabel sinceDate lastGiftDate lastGift giftCount`; `data-ct-each` (+ `data-ct-limit`) = `records estimates sinceRecords sinceEstimates gifts`. Record items: `count unit record date note kind` + `img[data-ct-photo]`. Gift items: `amount date`. **Estimate items: only `estimate` ("about N unit", always) and `unit`; `count`/`record` render nothing there.**
- **Links:** `data-ct-href="next"` = API href for give kinds, else the host's own `data-ct-href-<kind>` (e.g. `data-ct-href-volunteer="#volunteer"`), else removed. `data-ct-href="donate"` = hosted donate URL. Every `a[data-impact-donate]` inside a cloned template is rewritten too.
- **Motion hints:** `data-ct-animate="count|draw|reveal|arrive"` (`count` is ignored on estimates). `data-ct-live` on a `data-ct-each` list = live-arriving records are inserted there with `data-ct-new`. All motion is off under `prefers-reduced-motion`; strangers get no injected styles.
- **Hooks set by the layer:** `html[data-impact-active]`, `html[data-impact-donor="<state>"]`, `html[data-impact-live]` while polling; per region `data-impact-state="ready"` + `data-impact-variant="<name>"`; events `chartitable:ready` / `chartitable:update` on `document` (detail: state + variants, no names or numbers).
- **Safety:** API strings never go through innerHTML; API URLs pass `safeUrl`; host-authored attributes are trusted host markup. Hosts must label estimate containers visibly (e.g. "Your share, an estimate"); estimate items also get `.ct-estimate`, records `.ct-record`.
- **API (additive, `engine/types.ts`):** `hero.headline`, `hero.body`, `nextStep.label`, `donor { state, traits, gifts, giftCount }`, `rev`, `live { pollMs }`; `GET /donor-view?peek=1` (no visit row) and `GET /donor-pulse` → `{ recognized, rev }`.
